接管弹窗主操作被挤出首屏、日志页没有空状态、字号只有单一档位。

## 配色

近黑色阶，刻意不用纯黑 —— 留一点冷调，也让 `--bg-sunken` 有下沉空间。

| 变量            | 值                      | 用在哪                                          |
| --------------- | ----------------------- | ----------------------------------------------- |
| `--bg`          | `#0c0d0e`               | 窗口底。**必须与主进程 `backgroundColor` 一致** |
| `--bg-sidebar`  | `#0a0b0c`               | 侧边栏，比正文略深                              |
| `--bg-elevated` | `#131416`               | 卡片                                            |
| `--bg-hover`    | `#191a1d`               | hover 态                                        |
| `--border`      | `#1e2023`               | 层次主要由色阶承担，边线只做极淡的收边          |
| `--text-dim`    | `#85888f`               | 次要文字                                        |
| `--text-faint`  | `#5c5f66`               | 最弱的辅助文字（改版新增这一档）                |
| `--accent`      | `#6e7bf2`               | Linear 紫                                       |
| `--accent-soft` | `rgba(110,123,242,0.1)` | 导航选中态、下拉高亮、选中的选项                |

`--bg` 与主进程 `BrowserWindow.backgroundColor` 必须一致，否则窗口还没画出第一帧时会闪一下旧配色。
仓里有注释钉着这条。

### 为什么 logo 用色块 + 首字母，不用官方 SVG

官方标识是各家商标，随包分发有授权问题；几十家供应商的图标体量也远超这个界面本身。
色块能起到同样的作用 —— 让用户在一屏卡片里靠**颜色**一眼认出「哪个是哪家」。

认不出的供应商也必须拿到**稳定**的颜色：同一家每次渲染颜色一致，否则用户记住的颜色下次就变了，
比没有颜色更糟。所以走 djb2 散列落到固定兜底色板，兜底色板刻意避开 `--accent`，
免得「认不出的供应商」撞上界面的强调色。

匹配时**名称与 Base URL 都看**：用户常把卡片命名成「我的中转」这种跟品牌无关的名字，
但地址里往往留着 `api.deepseek.com`，那才是真正的线索。

有一处为可读性放弃了品牌忠实：Kimi 的品牌色是黑，直接用会糊进近黑底，
所以提一档明度到 `#3c3d47`（仍是中性灰）。这类取舍在 `vendor-brand.ts` 里都有就地注释。

## 三个缺陷是怎么修的

### 1. 接管弹窗主操作被挤出首屏（P0）

原实现是整个 `.modal` 滚动（`max-height:84vh; overflow-y:auto`）。
正文是「一次性授权说明 + 残余风险告警 + 目标文件 + 3 行改动对照表 + 凭证说明」，
在 `1120×728` 下放不下，于是「确认接管」被推到滚动区外 —— **用户看不到主操作**。

改成 flex 三段式：`.modal-head` 固定 + `.modal-body` 可滚 + `.modal-actions` 固定。
顺带修了对照表：`table-layout: fixed` 固定三列宽度，凭证值用等宽字体。
原来 64 字符的 token 会把「将改为」列撑变形，`ANTHROPIC_BASE_URL` 这个键名被断行。

### 2. 日志页没有空状态（P1）

`LogsView` 没有 empty 分支，无记录时是一片纯空白 —— 用户分不清「没有日志」和「页面坏了」。
补上与用量页一致的 `.empty` 虚线框空态。

### 3. 字号只有单一档位（P2）

全文只有 `13.5px` 一档，标题 / 正文 / 辅助只靠颜色区分，扫读困难。
补齐层级后，辅助文字降到 11px 并用 `--text-faint`。

### 另外两处是看截图才发现的

- **用量页：零记录时表头仍渲染**，一行表头杵在空状态上方，看着像表格没加载出来。
  改成表头跟着数据一起出现。
- **Kimi logo 几乎不可见**（见上节）。

这两处 `tsc`、lint、单测都看不出来 —— 只有看真实像素才发现得了。

## 被固化的契约（改版中确认过「不能动」）

以下选择器被 `scripts/e2e/run.js` 与 `scripts/smoke.js` 当契约用。
**布局可以在这些锚点内部重排，但 id / class / 文本 / 属性 / 结构关系一个都不能动**：

| 契约                                                                     | 谁在依赖    |
| ------------------------------------------------------------------------ | ----------- |
| `#claude-line` + `data-claude-state`（`off`/`active`/`pending`）         | e2e + smoke |
| `#btn-setup` / `#btn-disconnect` / `#btn-retakeover`                     | e2e + smoke |
| `#modal-root[hidden] { display: none }`                                  | e2e + smoke |
| `.modal h2` 的**文本**（「接管 Claude Code」「已接管」）                 | e2e         |
| `.modal-actions button` 的**文本**（「确认接管」「好」「取消」「保存」） | e2e + smoke |
| `.diff-table tbody tr td` 三列结构                                       | e2e         |
| `#provider-list .card` / `.card-title` / `.card-url` / `.combobox-list`  | smoke       |
| ProfileModal 的 `input` 数量 === 3，且 `inputs[1]` 是 BaseURL            | smoke       |
| `.main` 是滚动容器（`scrollHeight` 有效）                                | smoke       |

改版过程中据此避开了两个坑：

- **关闭按钮不能放进 `.modal-actions`** —— e2e 靠**文本**在 `.modal-actions` 里找按钮，
  多一个「关闭」会干扰定位。所以它留在 `.modal-head`。
- **关闭按钮的图标用 SVG，不用 `×` 字符** —— e2e 会读 `modal.textContent`，
  字符会掺进去。SVG 不贡献文本。

还有一条自己给自己定的：**下拉列表关闭时必须从 DOM 里摘掉**。
`Combobox` 原本就是条件渲染（`{open && filtered.length > 0 && ...}`），
`smoke.js:495` 断言 `card.querySelector('.combobox-list') === null`。
所以新加的箭头只切换 `open`，绝不改成「留着 DOM 用 CSS 隐藏」。

## 怎么验证

按 `CLAUDE.md` 第 2 节，界面改动的最低门槛是真起一个 Electron：

```bash
npm run typecheck          # 两个 tsconfig
npm run lint
npm test                   # 124 项
npm run build              # ← 不能省，见下
npm run e2e                # 5 个场景
```

### 一个真踩到的坑：e2e 绿了，但验的是旧代码

`scripts/e2e/run.js` 只断言 `dist/renderer/index.html` **存在**（595-596 行），**它从不构建**。
第一次跑 e2e 时 `dist/` 还是改动前的产物，全部通过 —— 但截图里还挂着已经删掉的卡片单选点。

**任何 e2e / 截图之前必须先 `npm run build`。** 绿不等于验到了新代码。

### 这次实际跑出来的

| 检查                                    | 结果                  |
| --------------------------------------- | --------------------- |
| `npm run typecheck`                     | 通过                  |
| `npm run lint`                          | 通过                  |
| `npm test`                              | **124 通过 / 0 失败** |
| `npm run format:check`                  | 通过                  |
| `npm run e2e`                           | 5 个场景全过          |
| CDP 行为断言（隔离 HOME + 真 Electron） | **34 项全过**         |

CDP 那份脚本在仓库外（`/tmp`），验的是**行为**不是观感：卡片结构、品牌色、
两栏网格、combobox 展开与收起（含失焦循环）、日志空态、弹窗三段几何、
「确认接管」是否在首屏内、对照表列宽、ProfileModal 的 3 个输入框及其顺序、侧边栏全部 id。

两条写这类检查时的教训：

- 列表是**条件渲染**的，隔离环境里没有可达的供应商 ⇒ `filtered.length === 0` ⇒ 列表根本不出现。
  得先起一个本地假的 `/v1/models` 上游，检查才有意义。失败的是**测试装置**，不是产品。
- 量「某段文字占了几行」不能用 `td.getBoundingClientRect().height / line-height` ——
  `td` 的高度含 padding，且一行里所有格子共享最高的那个的高度（三个格子报同一个数就是征兆）。
  要用 `Range.getClientRects().length`。
