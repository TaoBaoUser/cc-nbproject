## 一句话

**本地反向代理 + Electron 控制台**，让 Claude Code 切换 API 供应商时不需要重启。

做法是让 `ANTHROPIC_BASE_URL` 恒定为 `http://127.0.0.1:8787-8807`（本机代理），
切换供应商只改代理的路由目标。Claude Code 全程无感知。

```
Claude Code ──► 本机代理 :8787-8807 ──► 当前激活的供应商
                （base URL 只写一次，永不改）
                  ▲
                  └── Electron 窗口改这里的路由目标
```

| 层         | 用什么                          | 备注                                                             |

| 运行时依赖 | 仅 `react` + `react-dom`        | 其它全在 devDependencies                                         |

## 文件与路径（全部硬事实）

| 路径                                   | 是什么                                                | 权限                |
| -------------------------------------- | ----------------------------------------------------- | ------------------- |
| `~/.cc-nbproject/profiles.json`        | 供应商列表 + 设置 + 接管状态 + 本地准入凭证           | `0600`，目录 `0700` |
| `~/.cc-nbproject/usage.jsonl`          | 用量流水，每行一条 JSON                               | `0600`              |
| `~/.claude/settings.json`              | **用户的** Claude Code 配置。本工具唯一会改的用户文件 | `0600`              |
| `~/.claude/settings.json.bak.<时间戳>` | 首次接管前自动备份，**只产生一次**                    | —                   |

### `profiles.json` 的形状

```jsonc
{
  "version": 1,
  "activeId": "…",              // 当前激活的供应商
  "profiles": [ { "id", "name", "baseUrl", "apiKey", "modelMap", "createdAt" } ],
  "settings": {
    "port": 8787,               // 起始端口，被占则向上顺延，最多 20 次
    "localToken": "…64 位十六进制…",   // 本机代理的准入凭证，见下
    "takeover": null            // 接管状态快照；null = 从未接管过
  }
}
```

### 受管键只有两个

改动 `~/.claude/settings.json` 时**只碰** `env.ANTHROPIC_BASE_URL` 与
`env.ANTHROPIC_AUTH_TOKEN`。`ANTHROPIC_MODEL` 等模型相关键、`permissions`、
`hooks` 一概不动 —— 那些与走不走代理无关。

## 接管的语义（这是最容易搞错的部分）

**一次授权，长期记住；开应用才生效，关应用自动还原。**

| 时机               | 行为                                                               |
| ------------------ | ------------------------------------------------------------------ |
| 用户点「确认接管」 | 备份（仅首次）→ 写入两个受管键 → 记下 `previous`（接管前的真实值） |
| 应用启动           | 若此前授权过，**自动**再接管一次（不再询问），同时刷新 `previous`  |
| 应用退出           | **自动还原**成接管前的样子                                         |
| 点「断开接入」     | 还原 + 清除授权记忆（此后启动不再自动接管）                        |

**还原只走 `before-quit` 一个口子。** `window-all-closed` 在「应用正在退出」时
根本不触发（Cmd+Q 正是如此），把还原挂在它上面等于在最常见的退出路径上从不执行。

**用户手改过的键不动。** 还原是逐键三态判定：等于 `applied` 就回滚、已经是
`previous` 就跳过（幂等）、两者都不是（用户自己改过）就保持不动并报出来。

## 本地准入凭证（`localToken`）

代理监听 `127.0.0.1`，但「本机」不等于「本用户」：同机任何进程都能连上，
而代理会拿**用户真实的 API key** 去发请求。所以：

- 每次安装随机生成 32 字节（64 位十六进制）凭证，存在 `profiles.json`
- 接管时把它写进 Claude Code 的 `ANTHROPIC_AUTH_TOKEN`
- 代理只认它，认不出就回 `401 {"type":"unauthorized"}`

写进 Claude Code 的**不是用户的真实 key**，也不是任何固定常量 —— 固定常量
（老版本的 `cc-nbproject-managed`）等于把门钥匙公开贴在门上。

## 命令

```bash
npm install
npm run build      # ⚠️ 必须先构建：npm start 加载的是 dist/renderer/index.html
npm start          # 启动应用

npm test           # 单元测试（node --test，零依赖）
npm run lint       # ESLint
npm run format     # Prettier
npx tsc --noEmit   # 渲染进程类型检查

npm run e2e        # 真 Electron 端到端：接管 → 退出 → 校验文件已还原（隔离 HOME）
npm run smoke      # 渲染进程冒烟：连真实窗口去点（需先手动带调试端口启动，见下）
```

`npm run smoke` 需要另一个终端先跑：

```bash
npx electron . --remote-debugging-port=9222
```

## 已知坑（踩过，别再踩）

1. **`ELECTRON_RUN_AS_NODE=1`**。这个环境变量会让 Electron 退化成普通 Node 进程，
   `app` 直接是 `undefined`，报错是 `Cannot read properties of undefined
(reading 'requestSingleInstanceLock')` —— 看上去像主进程的 bug，其实是环境。
   跑 Electron 相关脚本时用 `env -u ELECTRON_RUN_AS_NODE`。

2. **`npm start` 之前必须 `npm run build`**。`dist/` 在 `.gitignore` 里，
   干净克隆直接 `npm start` 会白屏。

3. **单实例锁在模块顶层判定**。第二个实例会立刻退出，`--remote-debugging-port`
   根本不会打开。要用调试端口跑 `smoke.js`，得先退出正在运行的那个实例。

4. **端口会漂移**。8787 被占时代理顺延到 8788…8807。任何需要写地址的地方都必须
   取 `proxy.baseUrl`，**不能写死 8787** —— 写死会把一个连不上的地址写进用户配置。

5. **改渲染进程必须用真 Electron 验证**。`npm run lint` + `npx tsc --noEmit` 全绿
   证明不了它能渲染。这个项目已经出过两次「代码一跑就崩、lint 却全绿」。

6. **CDP 注入的页面代码，变量名会撞**。同一段页面代码里 `const card` 出现两次就是
   `SyntaxError`，而报错抛在页面里，从 Node 这边只看到一句含混的失败。
