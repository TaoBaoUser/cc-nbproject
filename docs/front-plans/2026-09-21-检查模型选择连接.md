## 1. 检查 key + 网址是否有模型列表可用

现状：聚焦模型输入框时会调用 `window.ccnb.listModels()` 拉取 `/v1/models`，失败原因会被翻译成可操作的提示（`describeFetchFailure`）。

- [x] 有 `/v1/models` 的供应商（如 OpenRouter）：能拉到模型，状态栏显示「可选 N 个模型」。
  → 已验证：`openrouter` 实测「可选 446 个模型」，候选 446 条；冒烟第 4/4b 步有断言。
- [x] 没有该接口的供应商（如 DeepSeek，实测 404）：提示「该供应商没有 /v1/models 接口，可直接手打模型 ID」，而不是当作错误。
  → 已验证：`company-ds` 实测文案一字不差，候选 0。
- [x] key 无效：提示认证失败，而不是卡在「正在拉取」。
  → 已验证：OpenRouter 的 `/v1/models` 不带 key 也返回 200，制造不出这条分支；
  改用要求认证的 `https://api.deepseek.com` + 无效 key，实测「认证失败 —— 请检查 API key，可直接手打模型 ID」。
- [x] 注意：`/v1/models` 不属于 Anthropic 兼容规范，覆盖面无保证，手动填写路径必须始终可用。
  → 已验证：认证失败状态下输入框仍可编辑（非禁用/非只读），输入 `deepseek-chat` 立即落盘。

  → 已验证：446 条 = 上游实际返回条数；冒烟第 4b 步还把「文案里的 N」和「候选数」钉在一起。
- [x] 猜对源模型名时出现「建议 xxx」chip，点一下即采纳并保存。
  → 已验证：两行都给出建议（「主模型：建议 deepseek/deepseek-v4-pro」等），点一下即落盘。

### 已完成：模型下拉固定、不能滚动

- 现象（原）：卡片「主模型」「后台小任务」的模型下拉是固定的，无法上下滚动选择。
- 原因（原）：用的是 `<input list>` + 原生 `<datalist>`，候选浮层由浏览器渲染，是样式与滚动都不可控的黑盒。
- 做法：渲染进程整体迁到 React + TypeScript + Vite，用自写的 `Combobox` 组件
  （[components/Combobox.tsx](../../src/renderer/components/Combobox.tsx)）替换原生 `datalist`：
  候选列表 `max-height: 240px` + `overflow-y: auto` 可滚动，支持边打边筛、↑↓ 高亮、Enter 选中、Esc 收起。
- 约束仍成立：无 `/v1/models` 接口时（DeepSeek 场景）候选为空，输入框退化为普通文本框，仍可手打任意模型 ID。
- 冒烟检查已加断言守护这条：[scripts/ui-smoke.js](../../scripts/ui-smoke.js) 会验证
  `.combobox-list` 真的能滚（`scrollHeight > clientHeight`）、输入 `flash` 后候选收窄且全部命中、键盘选中后立即落盘。
